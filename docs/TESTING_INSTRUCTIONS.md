
# Testing Instructions

This repository uses one dependency workflow: **uv 0.11.29** with CPython 3.12.13. The checked-in
`requirements.lock` is generated by `uv pip compile`; do not create or commit `uv.lock`.

## Clean environment installation

Install uv 0.11.29 using an approved uv installation method, then run from the repository root:

```bash
uv --version
make install
.venv/bin/python --version
```

`make install` runs these deterministic steps:

```bash
uv python install 3.12.13
uv venv --python 3.12.13 --clear .venv
uv pip sync --python .venv/bin/python --require-hashes requirements.lock
uv pip install --python .venv/bin/python --no-deps --editable .
```

The workflow always invokes `.venv/bin/python`; it does not rely on a global `python` alias.

## Validation and quality commands

```bash
make seed-check
make test
make lint
make type-check
make clean
make release-scan
```

After `source .venv/bin/activate`, the equivalent explicit test command is
`python -m pytest`. `make release-scan` depends on `make clean`, removes `.venv`, and then uses
uv's isolated managed Python. This prevents installed third-party files from being mistaken for
public repository content by the conservative scanner. Run `make install` again before further
development commands.

## Rebuilding the exact lock

With uv 0.11.29:

```bash
make lock
```

This resolves universally for Python 3.12 and records exact versions plus distribution hashes for
all direct and transitive dependencies declared in `requirements.in`. The editable local project
is installed separately with `--no-deps`, so that step neither resolves nor downloads packages.
Commit `requirements.lock`, not any resolver cache or environment directory.

The final release must document clean installation, built-in scenario execution,
API-off fallback, API-on GPT stages, audit-bundle validation, and the public URL.
